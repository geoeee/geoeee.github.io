Harness Engineering：从控制论到AI工程化实践

为什么98%的价值在"缰绳"而不在"马"

2025-05-05 AI harness agent engineering
📝 本文为大纲阶段，后续持续更新完善。

一、引子：一个反直觉的事实

Claude Code 的优秀体验，98.4% 来自工程设计而非模型能力。Anthropic——那个靠卖 token 赚钱的公司——主动劝你别用 Agent。问题不是 AI 不够强，而是我们不会"驾驭"。

二、What — Harness Engineering 是什么

2.1 定义

  • 不是 Prompt Engineering 的升级版
  • 是为 AI Agent 搭建"缰绳+马具"的系统工程
  • 核心：设计环境、构建反馈回路、将架构约束编成规则

2.2 本质：控制论（Cybernetics）

1948年维纳在《控制论》中提出：感知→决策→执行→反馈。这个模式在历史上出现了三次：

  • 瓦特离心调速器（18世纪）→ 工人从拧阀门变成设计调速器
  • Kubernetes（2010s）→ 工程师从重启服务变成声明期望状态
  • AI Harness（Now）→ 开发者从写代码变成设计 Agent 运行环境

共同点：人的角色从"执行者"变为"舵手"。

2.3 分类框架：Fowler 的两个维度

  • 维度一：自主性程度（人在环 → 半自主 → 全自主）
  • 维度二：交互模式（单次调用 → 多轮对话 → Agent循环）
  • 用这个矩阵定位你的系统在哪个象限

三、Why — 为什么现在需要它

3.1 模型能力已经"够用"，瓶颈在工程侧

同一个模型，不同 harness 效果天差地别。Claude Code vs 裸 API 调用的体验鸿沟，说明了一切。

3.2 过度架构是最大的坑

Anthropic 的经验：大多数场景优化单次 LLM 调用就够了。不要为了用 Agent 而用 Agent。判断标准：你的任务真的需要循环决策吗？

3.3 人必须控 Plan

Karpathy 观点：Plan 模式是危险的。AI 擅长执行，人擅长规划和判断。正确分工：人定方向 + AI 跑腿。

四、How — 核心设计模式

4.1 上下文工程

  • 持久化指令文件：AGENTS.md / .cursorrules / CLAUDE.md
  • 作用域上下文组装：按组织→项目→任务分层加载规则
  • 分层记忆：常驻摘要 / 按需细节 / 可搜索历史
  • 渐进式压缩：新对话保留细节，旧对话逐层压缩
  • 做梦整理：后台定期去重、清理、重组记忆

4.2 工作流编排

  • 探索-规划-行动循环：只读探索 → 与用户对齐的规划 → 有写权限的执行
  • 上下文隔离子Agent：不同阶段用独立上下文，避免污染
  • 检查点与回滚：执行过程中设置可回退的状态点

4.3 架构三层模型（Claude Code实践）

  • 入口层：适配不同使用方式（CLI/UI/API/CI）
  • 会话层：统一成同一种 agent turn 执行模型
  • 运行层：工具调度、权限治理、状态恢复、长会话管理

4.4 反馈与评测

  • 自动评测闭环：AI 生成评测集 → AI 模拟用户执行 → AI 生成报告
  • 自动优化循环：评测 → 发现问题 → 修改 → 再评测（可多轮）
  • 核心理念：AI First，入口层杜绝人力苦力活

五、实践指南：从0搭一个 Harness

5.1 最小可用版本

  • 一个好的系统提示（指令文件）
  • 一套工具定义
  • 一个执行循环

5.2 逐步升级路径

  1. 单次调用 + RAG → 解决80%的问题
  2. 加入工具调用 → 让 AI 能操作外部世界
  3. 加入循环 → 让 AI 能自我修正
  4. 加入记忆 → 让 AI 有持续性
  5. 加入子Agent → 让复杂任务可分解
  6. 加入评测 → 让系统可度量和优化

5.3 常见陷阱

  • 过早引入 Multi-Agent（先把单 Agent 做好）
  • 忽略上下文管理（token 爆炸 = 性能崩塌）
  • 没有评测就优化（没有度量就没有改进）

六、展望：从 Coding Agent 到通用 Agent

  • Claude Code 不只是 Coding 产品，是通用终端 Agent
  • Harness Engineering 的方法论适用于所有 Agent 场景
  • 谷歌 MCP 服务器：解决上下文膨胀的生态方案
  • 未来方向：Agent 的"操作系统"层

七、总结

Harness Engineering = 控制论在 AI 时代的工程实现
核心心法：不要让马跑得更快，要把缰绳设计得更好。

行动建议：从你当前的 AI 使用场景出发，识别瓶颈在模型还是在 harness。
